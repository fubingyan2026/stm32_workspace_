# 副电源板(SLAVER) ↔ 主机 RS485 通信协议（V5.0.0）

- **适用**：E1_SLAVER_POWER_CTU（STM32F103RC 副电源板）
- **更新**：2026-09-09
- **一句话说明**：主机（上位机）通过 RS485 问一句、板答一句。板从不主动发数据。
  E1_MASTER 与 E1_SLAVER 接在同一条 485 总线上，**帧头完全一样**，
  靠**数据里第一个字节的设备 ID** 区分是谁的命令、是谁的回答。

---

## 1. 总线参数

| 项目 | 值 |
|------|----|
| 电平 | RS485 半双工 |
| 引脚 | USART3：PB10(TX) / PB11(RX)，DE/RE 使能 = PC5（高电平发送） |
| 波特率 | 115200，8 数据位、无校验、1 停止位（8N1） |
| 终端/偏置 | 总线两端 120Ω 终端，一处 A/B 偏置（工程规范） |

## 2. 帧格式（与 E1_MASTER 完全一致）

```
[ 'z' ] [cmd] [len] [payload ...] [crc] [ '\n' ]
```

| 位置 | 字节数 | 含义 |
|------|--------|------|
| 0 | 1 | 帧头，固定 `0x7A`（字符 `z`） |
| 1 | 1 | 命令码 cmd（见 §4） |
| 2 | 1 | len = payload 的字节数 |
| 3… | len | 数据 payload |
| 之后 | 1 | CRC8 校验字节 |
| 最后 | 1 | 帧尾，固定 `0x0A`（字符 `\n`） |

- **整帧长度 = len + 5**。
- CRC8：多项式 `0x31`、初值 `0xFF`，覆盖 `帧头~payload`。
- 多字节数字一律**小端**（低字节在前）。

## 3. 设备 ID（重要）

帧头相同，**ID 放在 payload 第一个字节**：

| 设备 | ID |
|------|----|
| E1_MASTER（主电源板） | `0x01` |
| E1_SLAVER（本板/副电源板） | `0x02` |

- **主机 → 板**：`payload[0]` = 目标 ID。是 `0x02` 才处理，否则整帧忽略不回答。
- **板 → 主机**：`payload[0]` = 源 ID，固定 `0x02`。

## 4. 命令总表

应答命令码 = `0x80 | 下行命令码`。

| cmd | 方向 | 名称 | 请求 payload（len） | 应答 |
|-----|------|------|---------------------|------|
| 0x01 | 主机→板 | 读系统状态 | `[目标ID]`（1） | `0x81` |
| 0x02 | 主机→板 | 读电压 | `[目标ID]`（1） | `0x82` |
| 0x03 | 主机→板 | 读温度/VDDA | `[目标ID]`（1） | `0x83` |
| 0x04 | 主机→板 | 输出控制 | `[目标ID][位域][预留][亮度2B]`（5） | `0x84` |
| 0x05 | 主机→板 | 清除故障锁存 | `[目标ID][0x01]`（2） | `0x85` |
| 0x06 | 主机→板 | 升级请求（跳转 Boot） | `[目标ID][0x01]`（2） | `0x86`（已实现） |
| 0x07 | 主机→板 | 读 Boot/固件信息 | `[目标ID]`（1） | `0x87`：`[源ID][app_ver u16][meta_ver u16][fw_size u32][fw_sum u32][reboot u16][flags u8]`（16） |
| 0x7F | 板→主机 | 错误应答 | — | — |

> 命令码与 E1_MASTER 完全相同；本板升级 0x06 已实现（见 §5.6）。

## 5. 各命令请求/应答数据格式

应答 payload 一律：`[源ID(0x02)] [数据...]`。下表“偏移”指去掉源 ID 之后的数据位置。

### 5.1 读系统状态（0x01 → 0x81）

请求：`payload = [0x02]`（len=1）
应答：`payload = [0x02] [字节0 故障位] [字节1 输出/锁存位]`（len=3）

字节0（故障位，1=异常）：

| 位 | 名称 | 含义 |
|----|------|------|
| 0 | err_24v | 24V 降压电源故障/锁存 |
| 1 | err_12v | 12V_ISO 电源故障/锁存 |
| 2 | err_aux | AUX 输入缺失/低于阈值 |
| 3 | err_motor | MOTOR 输入缺失/低于阈值 |
| 4 | err_lsd1 | LSD1 输出故障/锁存 |
| 5 | err_lsd2 | LSD2 输出故障/锁存 |
| 6-7 | — | 预留 |

字节1（输出/锁存状态）：

| 位 | 名称 | 含义 |
|----|------|------|
| 0 | out_24v | 24V 实际输出 |
| 1 | out_12v | 12V_ISO 实际输出 |
| 2 | out_lsd1 | LSD1 实际输出 |
| 3 | out_lsd2 | LSD2 实际输出 |
| 4 | latch_active | 存在故障锁存 |
| 5-7 | — | 预留 |

### 5.2 读电压（0x02 → 0x82）

请求：`payload = [0x02]`（len=1）
应答：`payload = [0x02] [8B]`（len=9）

| 去掉源ID后偏移 | 长度 | 内容 | 单位 |
|--------|------|------|------|
| 0 | 2 | AUX 输入电压（uint16 LE） | mV |
| 2 | 2 | MOTOR 输入电压（uint16 LE） | mV |
| 4 | 2 | LSD1 节点电压（uint16 LE） | mV |
| 6 | 2 | LSD2 节点电压（uint16 LE） | mV |

### 5.3 读温度/VDDA（0x03 → 0x83）

请求：`payload = [0x02]`（len=1）
应答：`payload = [0x02] [4B]`（len=5）

| 去掉源ID后偏移 | 长度 | 内容 | 单位 |
|--------|------|------|------|
| 0 | 2 | MCU 温度（int16 LE） | 0.01℃ |
| 2 | 2 | VDDA 电压（uint16 LE） | mV |

### 5.4 输出控制（0x04 → 0x84）

请求：`payload = [0x02] [输出位域] [0x00] [亮度 2B LE]`（len=5）

| payload 字节 | 含义 |
|--------------|------|
| 0 | 目标 ID = 0x02 |
| 1 | 输出使能位域：bit0=24V、bit1=12V_ISO、bit2=LSD1、bit3=LSD2 |
| 2 | 预留，恒 0 |
| 3-4 | 补光灯亮度 0~1000（uint16 LE，单位 0.1%，即 1000=100%） |

应答：`payload = [0x02] [0x00]`（len=2，0x00=成功）

### 5.5 清除故障锁存（0x05 → 0x85）

请求：`payload = [0x02] [0x01]`（len=2）
应答：`payload = [0x02] [0x00]`（len=2）

### 5.6 升级请求（0x06 → 0x86，已实现）
请求：`payload = [0x02] [0x01]`（len=2）
应答：`payload = [0x02] [0x00]`，随后本板写升级标志并**复位进 Bootloader**。

> 相关 Boot/App 布局：Boot @ 0x08000000，AppA @ 0x08008000（详见
> `E1_CTU_BOOT/docs/boot_485_ymodem.md`）。

### 5.7 读 Boot/固件信息（0x07 → 0x87，已实现）

请求：`payload = [0x02]`（len=1）

应答 `0x87`，payload（16B，含源 ID）：
`[源ID][app_ver u16][meta_ver u16][fw_size u32][fw_checksum u32][reboot_counts u16][flags u8]`

- 读取共享 Boot Metadata（`0x0803E000`，**只读 peek，不写 Flash、不累加启动次数**）+ App 编译期版本；
- `flags`：bit0=metadata 有效、bit1=`upgrade_flag==1`、bit2=`upgrade_flag==2`；
- Boot 模式（无 App）下无应答；**`0x08–0x0F` 保留给 Boot 升级传输专用**。

### 5.8 错误应答（0x7F）

`payload = [0x02] [错误码]`（len=2）

| 错误码 | 含义 |
|--------|------|
| 0x00 | 无错误 |
| 0x01 | 未知命令 |
| 0x02 | 功能暂不支持 |
| 0x03 | 帧长度与命令不匹配 |

## 6. 完整示例

**读 E1_SLAVER 系统状态**：
```
主机发送: z 01 01 02 CRC \n      （z | cmd=01 读状态 | len=1 | 目标ID=0x02）
板应答:   z 81 03 02 B0 B1 CRC \n （z | 81 应答 | len=3 | 源ID=0x02 | 故障字节 | 输出字节）
```

**全部打开 4 路输出且补光 100%（亮度 1000 = 0x03E8）**：
```
z 04 05 02 0F 00 E8 03 CRC \n
```
逐字节：cmd=0x04，len=5，目标ID=0x02，输出位域=0x0F（24V+12V+LSD1+LSD2），预留=0x00，
亮度低字节 0xE8、高字节 0x03（=1000）。

## 7. 与 E1_MASTER 的关系

- 帧头、CRC、命令码、设备 ID 机制完全一致；
- E1_MASTER ID=`0x01`、E1_SLAVER ID=`0x02`；
- 数据内容按板不同：电压本板为 AUX/MOTOR/LSD1/LSD2，主板的为 VIN/VIN_DC-DC；
  主机通过应答源 ID 区分数据来自哪块板。
