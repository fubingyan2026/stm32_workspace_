## 1. 阶段工作概述

在 E1_Master_Power_Manage 分层架构基础上，为量产主控板完成了可编译的分层固件骨架，并围绕「上电流程 / 急停语义 / RS485 通信 / 采样换算」进行了多轮重构与实机调试。

### 1.1 固件架构（已落地并通过 Debug 构建）

| 层 | 内容 |
|----|----|
| device_drivers | drv_systick / drv_adc(单 ADC1 7ch DMA) / drv_cd4051b / drv_pwm(TIM4 LED+双风扇) / drv_led / drv_buzzer(TIM3_CH3, 占空比 0-50%) / drv_fan(EXTI 测速) / drv_power / drv_status / drv_log_uart(USART1 TX) / drv_uart(USART3 DMA TX队列+RX circular/IDLE→kfifo) / dev_rs485(DE/RE 半双工封装) |
| service | srv_adc(VREFINT 校准+NTC+MCU 温度典型参数+CD4051B E-STOP 双冗余) / srv_pwr_ctrl(默认 5 步上电 FSM) / srv_pwr_det(电源监测+急停双判据+常开轨使能门控) / srv_fan_ctrl / srv_com_mst(z 帧协议，protocol_parser/packer) |
| applications | app_fault_policy(急停只控 MOTOR，MOTOR 门控管理) / app_status_report(MOTOR 异常按急停门控) / app_status_indicator |
| tasks | app_main / com_task(含 485 低频自检发送，调试宏) / fan_task / led_task / sample_task / power_task / log_task(本地 UART+RTT 双后端) |

### 1.2 共享层改动（public_layer/m_middlewares）
- `algorithm/math/utils_math.{c,h}`：新增通用边沿检测 `utils_edge_det / utils_edge_detect / utils_edge_det_init`，工程内边沿检测统一复用。

### 1.3 通信协议（V2.0.0）
- 帧格式（与 G0 上位机协议同构）：`[z][cmd][data_len][payload][CRC8][\n]`，CRC8 多项式 0x31、初值 0xFF，总长 = data_len+5。
- 命令：0x01 读状态 / 0x02 读温度 / 0x03 读电压 / 0x10 控制（蜂鸣器导通占空比 0-50%）/ 0x11 升级预留；应答 cmd=0x80|cmd，错误帧 0x7F。
- 解析 `protocol_parser`、打包 `protocol_packer`（服务层 srv_com_mst），驱动层 dev_rs485 + drv_uart 只做字节搬运与 DE/RE 方向控制。

### 1.4 上位机（host/）
- PySide6 + pyserial：串口选择/连接、手动查询、蜂鸣器滑杆(0-50%)、自动轮询、固定槽位数据区（未读取显示 `--`，不折叠）、日志清空按钮。

## 2. 电源语义演进与最终定义

| 阶段 | 说明 |
|------|------|
| 初版 | 顺序上电 FSM（VIN→24V→AUX→MOTOR，PGD 门控 + 超时） |
| V2/V3 | 迭代为「VIN/24V/AUX 常开 + MOTOR 独立受控」 |
| V4 | 全接管 5 步上电流程（含 AUX 成功后使能、急停全关） |
| V5（当前） | **AUX 初始化直接使能（不参与等待）；VIN_DC-DC / 24V 按 5 步默认流程门控；急停只控制 MOTOR；MOTOR 延后使能（上电成功后自动生效）** |

### 2.1 默认上电流程（程序启动自动执行）
1. 采样 VIN ∈ 36~58V；
2. 检测 VIN_DC-DC ≥ 90%·VIN；
3. 使能 VIN_DC-DC_EN，延迟 100ms；
4. 使能 DC_DC_24V_EN；
5. DC_DC_24V_PGOOD 与 LM5060_PGOOD 均高 → 上电成功（POWERED）。

### 2.2 电源轨控制语义
- **AUX**：初始化即直接使能，不参与任何等待；
- **VIN_DC-DC / DC_DC_24V**：按 5 步流程门控，成功后持续供电；
- **急停/故障不关断 VIN/24V/AUX**（仅作状态监测告警，监测按“使能门控”进行，未使能轨 PGD 低不上报错误）；
- **MOTOR_EN**（受控负载轨）：
  - 硬性前提：上电成功(POWERED)后才有资格使能；
  - 延后设定：未上电成功时的使能请求被记录，POWERED 后自动生效；
  - `app_fault_policy` 门控：`未锁存 && 已上电 && 未急停` → 使能；急停按下/MOTOR PGD 丢失 → 立即关断并锁存，急停释放解除。

## 3. 实机调试与日志分析

### 3.1 已验证行为（正常）
- VIN 输入电压判定正常（VIN≈40.5V）；VIN_DC-DC 达到 VIN 的 ~99%，步骤 1/2 快速通过。
- 步骤 3/4 顺序使能 VIN_DC-DC_EN、DC_DC_24V_EN。
- 急停按下后仅 MOTOR_EN 被关断，VIN/24V/AUX 不受影响、流程继续 —— 符合「急停只控制 MOTOR」。

### 3.2 阻塞问题：步骤 5 卡在「双 PGD」
- 现象：t≈127ms 两路 PGD 曾同时变高，随后 LM5060_PGD 掉低且持续为 0（跨 2s），DC24V_PGD / 12V PGOOD / VIN_DC-DC≈40.2V 均正常 → VIN_DC-DC 母线实际仍在供电。
- 时间点紧邻 DC_DC_24V_EN 使能后 ~20-26ms。
- 推断：**LM5060_PGOOD 网络异常，或 24V 使能瞬间冲击导致 LM5060 进入 OCP/打嗝保护（未真正闩锁关断）**；需硬件层确认。

### 3.3 采样/换算类修复（已解决）
1. **MCU 内部温度恒为 0**：F103 无出厂温度校准（TS_CAL1/2 读回 0xFFFF）→ 增加典型参数兜底（V25=1.43V、斜率 4.3mV/℃）。
2. **MCU 加热后温度反向下降**：F1 温度传感器电压随温度升高而**下降**，原公式斜率符号错误 → 改用手册公式 `T=(V25−V_sense)/4.3+25`，方向已正确。
3. **NTC1 读数异常（≈-44℃）**：疑似探头未接或分压/B 参数与实物不符，待实机标定。

### 3.4 状态上报规则调整
- `MOTOR 电源异常` 上报条件收敛为：**急停未按下 且 MOTOR_POWER_PGD=0**（急停中 MOTOR 关断属正常，不上报异常），文档同步。

### 3.5 485 通信联调辅助
- 固件加入**低频自检发送**（`COM_TEST_TX_ENABLE`，默认 2s 一帧合法 z 帧 0x81），便于示波器/上位机验证总线与 DE/RE 方向切换；量产需置 0 关闭。

4. [低] 共享库 protocol_parser 告警清理；`drv_uart_recover()` 周期兜底调用尚未接入 com_task。
