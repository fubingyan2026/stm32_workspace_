# 主电源板(CTU) ↔ 主机 RS485 通信协议（V5.0.0）

- **适用**：E1_MASTER_POWER_CTU（STM32F103RC 主电源板）
- **更新**：2026-09-09
- **一句话说明**：主机（上位机）通过 RS485 问一句、板答一句。板从不主动发数据。
  E1_MASTER 与 E1_SLAVER 两块板接在同一条 485 总线上，帧头完全一样，
  靠**数据里第一个字节的设备 ID** 区分是谁的命令、是谁的回答。

---

## 1. 总线参数

| 项目 | 值 |
|------|----|
| 电平 | RS485 半双工 |
| 引脚 | USART3：PB10(TX) / PB11(RX)，DE/RE 使能 = PC5（高电平发送） |
| 波特率 | 115200，8 数据位、无校验、1 停止位（8N1） |
| 终端/偏置 | 总线两端 120Ω 终端，一处 A/B 偏置（工程规范） |

## 2. 帧格式（两块板完全一致）

```
[ 'z' ] [cmd] [len] [payload ...] [crc] [ '\n' ]
```

| 位置 | 字节数 | 含义 |
|------|--------|------|
| 0 | 1 | 帧头，固定 `0x7A`（字符 `z`） |
| 1 | 1 | 命令码 cmd（见 §4） |
| 2 | 1 | len = payload 的字节数 |
| 3… | len | 数据 payload |
| 之后 | 1 | CRC8 校验字节 |
| 最后 | 1 | 帧尾，固定 `0x0A`（字符换行 `\n`） |

- **整帧长度 = len + 5**。
- CRC8：多项式 `0x31`、初值 `0xFF`，覆盖 `帧头~payload` 全部字节。
- 帧尾 `\n` 只用来方便抓包/调试，不参与长度判断。
- 多字节数字一律**小端**（低字节在前）。

## 3. 设备 ID（重要，先看这个）

两块板帧头相同，**ID 放在 payload 的第一个字节**：

| 设备 | ID |
|------|----|
| E1_MASTER（本板/主电源板） | `0x01` |
| E1_SLAVER（副电源板） | `0x02` |

- **主机 → 板（下行）**：`payload[0]` = 想发给哪块板（目标 ID）。
  例：payload = `[0x01, ...]` 只发给 E1_MASTER。
  ID 不是自己 → **整帧忽略，不回答**。
- **板 → 主机（上行）**：`payload[0]` = 自己是哪块板（源 ID）。
  例：E1_MASTER 应答 payload = `[0x01, ...]`。
- 这样两块板同时挂线也不会因为帧头不同而误解析，也不会抢着回答。

## 4. 命令总表

应答命令码 = `0x80 | 下行命令码`（例如读状态下行 `0x01`，应答 `0x81`）。

| cmd | 方向 | 名称 | 请求 payload（len） | 应答 |
|-----|------|------|---------------------|------|
| 0x01 | 主机→板 | 读系统状态 | `[目标ID]`（1） | `0x81` |
| 0x02 | 主机→板 | 读电压 | `[目标ID]`（1） | `0x82` |
| 0x03 | 主机→板 | 读温度 | `[目标ID]`（1） | `0x83` |
| 0x04 | 主机→板 | 控制（蜂鸣器） | `[目标ID][占空比]`（2） | `0x84` |
| 0x05 | 主机→板 | 清除故障锁存 | `[目标ID][0x01]`（2） | `0x85` |
| 0x06 | 主机→板 | 升级请求（预留） | `[目标ID][0x01]`（2） | `0x7F`（暂不支持） |
| 0x7F | 板→主机 | 错误应答 | — | — |

> 命令码与 E1_SLAVER 完全相同，两板只是应答里的数据内容不同。

## 5. 各命令的请求/应答数据格式

应答 payload 一律是：`[源ID] [数据...]`。下表中“偏移”指**去掉源 ID 之后**的数据位置。

### 5.1 读系统状态（0x01 → 0x81）

请求：`payload = [目标ID]`（len=1）

应答：`payload = [源ID] [状态字节0] [状态字节1]`（len=3）

状态字节0（bit 从低到高）：

| 位 | 名称 | 含义 |
|----|------|------|
| 0 | stop_key | 1 = 有效急停触发 |
| 1 | err_12v | 1 = 12V 电源异常 |
| 2 | err_24v | 1 = 24V 降压电源异常 |
| 3 | err_vin_dcdc | 1 = VIN_DC-DC(LM5060) 异常 |
| 4 | err_aux | 1 = 辅助电源 AUX 异常 |
| 5 | err_motor | 1 = 电机电源异常（急停未按下 且 MOTOR PGD=0） |
| 6-7 | — | 预留，恒 0 |

状态字节1：

| 位 | 名称 | 含义 |
|----|------|------|
| 0 | err_fan0 | 1 = 风扇0 异常 |
| 1 | err_fan1 | 1 = 风扇1 异常 |
| 2 | err_ntc1 | 1 = NTC1 未连接 |
| 3 | err_ntc2 | 1 = NTC2 未连接 |
| 4-7 | — | 预留，恒 0 |

> 急停说明：只有「数字急停按下 **且** CD4051B 冗余回路也确认断开」才算有效急停（bit0=1）。
> PGD 类位按原始电平上报，轨尚未使能时也会是 1，属正常现象。

### 5.2 读电压（0x02 → 0x82）

请求：`payload = [目标ID]`（len=1）

应答：`payload = [源ID] [VIN 2B] [VIN_DC-DC 2B]`（len=5）

| 去掉源ID后偏移 | 长度 | 内容 | 单位 |
|--------|------|------|------|
| 0 | 2 | VIN 主输入电压（uint16 LE） | mV |
| 2 | 2 | VIN_DC-DC 电压（uint16 LE） | mV |

### 5.3 读温度（0x03 → 0x83）

请求：`payload = [目标ID]`（len=1）

应答：`payload = [源ID] [6B]`（len=7）

| 去掉源ID后偏移 | 长度 | 内容 | 单位 |
|--------|------|------|------|
| 0 | 2 | NTC1 温度（int16 LE） | 0.01℃（如 2500 = 25.00℃） |
| 2 | 2 | NTC2 温度（int16 LE） | 0.01℃ |
| 4 | 2 | MCU 内部温度（int16 LE） | 0.01℃ |

### 5.4 控制-蜂鸣器（0x04 → 0x84）

请求：`payload = [目标ID] [占空比]`（len=2）

| payload 字节 | 含义 |
|--------------|------|
| 0 | 目标 ID（0x01=本板） |
| 1 | 蜂鸣器导通占空比 0~50%（0=静音，50=最响；超过 50 会按 50 处理） |

应答：`payload = [源ID] [0x00]`（len=2，0x00=成功）

### 5.5 清除故障锁存（0x05 → 0x85）

请求：`payload = [目标ID] [0x01]`（len=2，第 2 字节固定 0x01）

清除板上的保护锁存；清除后若“已上电 + 未急停”，会自动重新使能 MOTOR。

应答：`payload = [源ID] [0x00]`（len=2）

### 5.6 升级请求（0x06，预留）

请求：`payload = [目标ID] [0x01]`（len=2）
本阶段**不支持**，应答：`cmd=0x7F，payload=[源ID] [0x02]`（0x02=功能暂不支持）。

### 5.7 错误应答（0x7F）

`payload = [源ID] [错误码]`（len=2）

| 错误码 | 含义 |
|--------|------|
| 0x00 | 无错误 |
| 0x01 | 未知命令 |
| 0x02 | 功能暂不支持 |
| 0x03 | 帧长度与命令不匹配 |

## 6. 完整示例（读 E1_MASTER 的系统状态）

**主机发送**（对 E1_MASTER，cmd=0x01，payload=[0x01]）：
```
z 01 01 01 CRC \n
```
- `z` 帧头
- `01` cmd = 读系统状态
- `01` len = 1
- `01` payload[0] = 目标 ID = E1_MASTER
- `CRC` 覆盖 `z 01 01 01`
- `\n` 帧尾

**E1_MASTER 应答**：
```
z 81 03 01 B0 B1 CRC \n
```
- `81` = 0x80|0x01（读状态应答）
- `03` len = 3
- `01` payload[0] = 源 ID = E1_MASTER
- `B0 B1` = 两个状态字节（见 §5.1）
- `CRC \n`

如果主机把目标 ID 写成 `0x02`，则是发给 E1_SLAVER，本板不会回答。

## 7. 与 E1_SLAVER 的关系

- 帧头、CRC、命令码、设备 ID 机制完全一致；
- E1_MASTER ID = `0x01`，E1_SLAVER ID = `0x02`；
- 各命令应答里的“数据内容”两块板不同（如 E1_MASTER 电压是 VIN/VIN_DC-DC，
  E1_SLAVER 是 AUX/MOTOR/LSD1/LSD2），见 `E1_SLAVER_POWER_CTU/docs/protocol_slaver_485.md`。
