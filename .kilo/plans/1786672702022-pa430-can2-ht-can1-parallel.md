# 修复 CAN FD 数据段位时序不匹配（MCU 发得出、对方收不到）

## 现象
- MCU 能接收到其它设备（电机/检测器）的 5M 数据段 CAN FD 帧；
- 但其它设备接收不到 MCU 发送的 5M 数据段帧（经典 CAN 1M 双向正常）。

## 根因（已定位）
Motorevo 电机 CAN FD 位时序（docs/Motorevo电机CAN协议文档.md §1.3，电机主频 170MHz）：
| | 仲裁域 | 数据域 |
|---|---|---|
| 电机 | BPR=10, Seg1=13, Seg2=3 → 采样 82.3% | BPR=1, Seg1=25, **Seg2=8** → 采样 76.47% |
| MCU 当前 | prescaler=8, Seg1=14, Seg2=5 → 75% | prescaler=2, Seg1=12, **Seg2=3** → 81.25% |

CAN FD 数据段硬规则：**发送方 Seg2 ≥ 接收方 Seg2**。
- 电机数据段 Seg2 = 8 tq @170MHz = 47ns；MCU 数据段 Seg2 = 3 tq = 37.5ns。
- MCU 发 → 电机收：37.5 < 47 → 违反规则 → 电机收不到（本现象）。
- 电机发 → MCU 收：47 ≥ 37.5 → 满足 → MCU 收得到（本现象）。
仲裁域同样有 mismatch，但 1M 位时间长、容差大，不暴露。

## 修复
把 MCU 数据段 Seg2 提到 ≥ 47ns，并顺带对齐采样点，保持 5M：
- `DataTimeSeg1` 12 → 11、`DataTimeSeg2` 3 → 4（`DataPrescaler` 保持 2，`DataSyncJumpWidth` 保持 2）。
- 结果：位速率仍 5M（2×(1+11+4)=32 tq=200ns）、采样点 75%（贴近电机 76.47%）、Seg2=4 tq=50ns ≥ 47ns ✓。

### 实现位置
位时序在 CubeMX 生成的 `Core/Src/fdcan.c`（`MX_FDCANx_Init` 的 `hfdcan.Init.DataTimeSeg1/2`），
不宜直接改生成区。改为在 `device_drivers/drv_can.c` 的 `drv_can_init()` 每通道循环内、
`HAL_FDCAN_Start` **之前**（INIT 态，可写 DBTP）直接覆盖 DBTP 数据段字段：

```c
/* 数据段位时序对齐 Motorevo 电机 §1.3：Seg1=11, Seg2=4, SJW=2（采样 75%，Seg2 50ns）
 * 满足「发送方 Seg2 ≥ 接收方 Seg2」(电机 Seg2=47ns)，否则对方收不到本机 5M 数据 */
MODIFY_REG(s_hfdcan[ch]->Instance->DBTP,
    FDCAN_DBTP_DTSEG1 | FDCAN_DBTP_DTSEG2 | FDCAN_DBTP_DSJW,
    ((DRV_CAN_DATA_TSEG1 - 1U) << FDCAN_DBTP_DTSEG1_Pos)
    | ((DRV_CAN_DATA_TSEG2 - 1U) << FDCAN_DBTP_DTSEG2_Pos)
    | ((DRV_CAN_DATA_SJW - 1U) << FDCAN_DBTP_DSJW_Pos));
```

新增宏（放在 `DRV_CAN_TDC_*` 附近）：
```c
#define DRV_CAN_DATA_TSEG1 11U
#define DRV_CAN_DATA_TSEG2 4U
#define DRV_CAN_DATA_SJW 2U
```

- DBTP 寄存器值 = (Seg-1)，与 HAL 写 NBTP/DBTP 的编码一致；`MODIFY_REG` 只改这三个字段，
  保留 DBRP 与 TDC 位（TDC 由 `HAL_FDCAN_EnableTxDelayCompensation` 置位）。
- 放置顺序：先 `ConfigTxDelayCompensation`/`EnableTxDelayCompensation`，再本 MODIFY_REG（或反之均可，
  因 MODIFY_REG 不清 TDC 位）。

## 验证
1. `cmd /c build.bat` 通过。
2. 烧录后：电机应能收到 MCU 的 5M 数据段帧；接电机时日志出现 `电机 ID=1 已收到反馈`，
   且 MCU 侧不再单向（MCU 发、电机也能回）。
3. 若仍失败：仲裁域也按电机 spec 对齐（prescaler=10, Seg1=12, Seg2=3 → 采样 81.25%），
   但仲裁域当前工作正常，优先级低。

## 注意
- 本修复只改数据段 Seg1/Seg2，不动数据段波特率（5M）、仲裁段（1M）与 TDC。
- 若后续 CubeMX 重新生成代码，需把 `DataTimeSeg1=11 / DataTimeSeg2=4` 同步进 `.ioc`
  （FDCAN2.DataTimeSeg1 / FDCAN2.DataTimeSeg2），或保留 drv_can.c 里的 DBTP 覆盖。
